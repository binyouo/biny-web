# Biny 官网

产品首页、下载页与中文使用文档。基于 Vite、React 和 Tailwind CSS，构建结果是静态文件。

## 本地开发

需要 Node.js 22.12 或更新版本，以及 pnpm 10.6.5。克隆本仓库即可独立构建：

```bash
cd website
pnpm install --frozen-lockfile --ignore-scripts
pnpm dev
```

开发地址默认为 `http://localhost:5173/zh`。验证和预览：

```bash
pnpm test
pnpm typecheck
pnpm build
pnpm preview
```

网站源码由 `biny-web` 仓库维护。`vendor/biny/` 保存交互演示使用的客户端、共享模块及类型依赖快照；仅用于类型检查的后端模块保留 `.d.ts`，不携带执行实现。模块引用均在本仓库内，版本元信息位于 `vendor/biny/package.json`。更新演示快照时，需要同步依赖并运行完整网站测试和构建。

## 页面与职责

| 路径 | 内容 |
| --- | --- |
| `/zh` | 产品首屏、桌面端演示、能力分区、模型服务与桌面／终端入口 |
| `/zh#download` | 首页内的桌面发布信息、npm 安装与源码启动 |
| `/zh/download`、`/download` | 兼容旧地址，转到首页下载区，保留查询参数与锚点 |
| `/zh/docs` | 中文文档概览 |
| `/zh/docs/<slug>` | 安装、快速开始、会话、Provider、记忆、工具、扩展与任务指南 |

`/` 转到 `/zh`；`/docs` 和 `/docs/<slug>` 转到对应中文文档路径，保留查询参数与锚点。未知文档展示明确的 404 内容。

## 内容维护

文档按用户操作编写，发布前核对当前 Biny 的源码、命令帮助与设置入口。官网不直接发布本地 `docs/specs/` 中的内部实现笔记。

- 项目链接统一来自 `src/lib/site.ts`，不在页面中保存版本号。
- 产品演示使用预置场景，访客操作只改变演示状态，不连接模型、不读写真实项目。
- 首页的功能示意不冒充产品截图；修改能力描述时同时检查演示文案与对应指南。
- 文档搜索覆盖标题、关键词、描述与正文；多词查询要求每个词都匹配同一篇文章。
- 新增文章时为页面和章节设置唯一标识，并同步 `public/sitemap.xml`。
- npm 安装包与当前源码可能处于不同版本，文档命令仍应按所使用版本的帮助核对。

## 视觉样式

配色取自桌面端图标：银白头发、近黑底色与冷灰阴影。深色页面用 `#131316` 近黑底，浅色页面用近白的纸感灰 `#f4f4f1`；整套令牌不含彩色强调——深色用冷银白、浅色用冷炭灰。层级靠字号、留白与明度拉开，不用彩色渐变或光晕。

视觉语言是像素风，参考 claude.dev 与 Kimi 招聘站的终端式排版：

- **字体**：整站标签、导航、编号、标题辅助文字使用 **Fusion Pixel 12px**（自托管，`src/assets/fusion-pixel-12px-mono-zh.otf`，SIL OFL 1.1，授权见同目录 `fusion-pixel-LICENSE.txt`）。它同时覆盖中文、英文与制表符/块字符，和参考站用的是同一款。中文大标题仍用 Noto Sans SC Variable 的 800–900 字重——像素字放大后笔画会散，标题保持无衬线更耐读；正文同理。像素字体元素关闭了字体平滑（`-webkit-font-smoothing: none`），否则边缘会糊。
- **形状**：所有卡片、按钮、输入框一律直角（`--site-radius: 0`），阴影改成硬投影 `3px 3px 0`，按钮悬停是「位移 + 阴影收缩」的两帧式反馈，不用柔光。模型服务是一行像素胶囊。
- **导航**：像素字，项在悬停或当前页时出现 `[ ]` 括号，模仿终端快捷键；下载入口是带硬投影的方块按钮。
- **标题**：首屏 `clamp(42px, 7.2vw, 116px)`，分区标题最大 62px，统一加一档硬文字投影。强调词只加一道像素下划线，不加光晕。
- **像素场景背景**：背景不是纹理，而是三张整幅像素插画（`public/scenes/window.png`、`horizon.png`、`orbit.png`），由 `scripts/make-scenes.py` 生成：先在 720×450 的逻辑画布上用**有序抖动（Bayer 4×4）**画，再用 NEAREST 放大 3 倍，全程没有抗锯齿。场景层固定在视口（`position: fixed`），随滚动进度在"窗 → 地平线 → 轨道"之间交叉淡入，进度由 `--scene-progress` 驱动，只写 CSS 变量、不触发重渲染。插画是黑白的，亮色主题整体反相并降低不透明度。正文分区各自铺一层底色或半透明底，保证点阵不会穿过文字。减少动态效果时停在第一张。
- **能力卡片**：每张卡带 `01 COMPUTER HISTORY` 这样的像素编号标签；窗口圆点、步骤条、聊天气泡都改成直角。
- **模型服务**：一行像素胶囊，图标 + 名称，悬停只换边框。

导航用 sticky 定位：首页未滚动时透明，滚过一小段后变成带模糊的玻璃底；内页直接使用玻璃底，因此文档、下载页不再需要为固定导航预留顶部内边距。

首页是编辑式版式，不是每个分区都居中：

1. **封面**：左对齐大字，说明与按钮排在一条分隔线之下，右侧留出场景插画。
2. **演示舞台**：桌面演示单独成段，不挂在封面里。
3. **能力区**：左栏标题随滚动停住（`position: sticky`），右栏四张卡片自行滚动；左栏底部一行像素状态（`01 / 04`、向下滚动）纯装饰。
4. **入口**：左栏标题同样 sticky，右栏桌面／终端两张卡。
5. **无字间歇**：一整幅场景，只留相机取景框的四个角标，不放任何文案——这是刻意的留白，让读者停下来看一眼画面。
6. **收尾**：左对齐的最后一屏。

能力卡片为双列，窄屏单列；模型服务是一排胶囊，不再做成九宫格卡片。

功能区采用四张紧凑双列卡片：Computer History、Computer Use、Memory / Sleep 和 Rich Markdown；音乐并入 Rich Markdown 模式。窄屏切为单列。每张只保留短标题与演示画面，模型区使用客户端同源的本地品牌图标。播放、重播与模式切换控件放在画面内部，仅在悬停、键盘聚焦或触屏设备上显示。

Computer History 用「刚才看过一家旅馆 → 问名字 → 找回网页线索」说明全局活动回忆，结果在开播约 2.5 秒后出现，并停留 6 秒供阅读。Memory 用跨对话的旅行偏好说明 Sleep。这两张卡片为功能示意，使用无障碍说明标明，不读取访客活动。动画可暂停、重播和选择步骤，卡片离开视口或标签页进入后台时停止推进；减少动态效果时直接呈现结果。

渲染展示只保留聊天区域，使用 `render-demo.html` 独立入口隔离样式，直接导入客户端的 `MarkdownContent`、`AppearanceContext` 与原有样式。`src/demo/renderSamples.ts` 中的预置 Markdown 经真实客户端路径解析，Mermaid、Infographic、KaTeX、表格和 Strudel 控件均可交互；没有预渲染图片、手工信息图或模拟音乐频谱。点击模式标签可以切换，操作聊天内部控件会暂停轮播。音乐使用内置三角波合成器，点击才播放，离屏或切换后台会卸载播放器并停止音频。iframe 消息校验来源窗口与同源地址，不连接模型或桌面桥接。支持模式的说明见 `/zh/docs/rich-content`。

Computer Use 使用同一个 `client-demo.html?scene=computer` 入口，复用真实 App、Composer、消息时间线与浏览器侧栏。通过客户端菜单事件收起侧栏，预置的 ComputerObserve / ComputerAction 事件驱动本地原创「慢慢逛」网页，展示搜索和打开地点。没有第三方产品截图，不连接操作系统或模型。这张次级卡片仅播放动画，内层窗口设为 inert 并屏蔽指针事件；隐藏应用导航和浏览器工具按钮，不提供放大、输入或接管入口，只在画面内保留悬停重播。重播会重置场景。离屏或后台暂停，减少动态效果时直接呈现结果。

### 交互演示

首页在 iframe 中加载 `client-demo.html`。入口安装内存中的 `window.biny` 数据适配器，然后挂载 `vendor/biny/src/desktop/renderer/src/App.tsx`，使用真实 App、Sidebar、Composer、消息时间线、菜单、权限卡和完整样式入口。官网样式不会进入 iframe。

演示采用深色 `vscode_dark`、系统字体 15px、250px 侧栏、372px 文件面板，以及 1353×828 的窗口画布。嵌入区域整体等比缩放；“放大查看”扩大展示区域，不改写桌面端的内部布局。macOS 原生窗口控制点由少量网页样式补齐，仅作外观展示。

`desktopDemo.ts` 将预置场景转为 Desktop 文档和运行事件，复用运行状态归约与权限确认规则。访客可以切换会话、重播、快进、停止、展开工具结果、使用原始模型和权限菜单。快进停在待批准的操作；高风险操作要求完整 `yes`；拒绝后停止后续脚本。重播会取消旧回合并等到新会话选中后才继续发送事件。

新会话欢迎区的头像、标题、副标题、建议短语与输入框共用居中轴线。标题按可用宽度自然换行，保留完整的欢迎内容。

网页演示保留设置按钮的位置，但禁用该入口，也不通过菜单打开设置面板；桌面端设置功能正常可用。

右栏的文件树、变更记录、Git 状态、终端输出、浏览器页面与引用均由内存数据提供。文件变更复用 Desktop 的事件与时间线归约；浏览器保留真实面板控件，默认网页内容由禁用脚本的本地 iframe 展示，直接挂在真实浏览器的内容槽内，不再复制原生窗口坐标为固定覆盖层；Computer Use 示例页只允许脚本，保持不透明沙盒来源，接收消息同时校验父窗口和来源地址；父页面校验精确的 iframe 窗口及沙盒来源。终端输入只回显，不执行命令。

消息、文件与命令结果都是内存中的预置数据，刷新即重置。输入框接受场景中的原始问题；其他问题提示使用桌面端。系统、模型和未提供的管理功能由适配器明确拒绝，不执行真实操作。此边界不代表桌面端的能力限制。

本地开发与构建只依赖本仓库中声明的依赖和客户端快照，可将 `website/` 独立复制到空目录安装、测试和构建。构建后的 `dist/` 是完整静态产物，可独立托管。原生窗口管理、系统权限、文件对话框与真实模型运行需在桌面端体验。

## 下载状态

下载页请求 npm 最新版本与 GitHub 公开 Release 列表，选取首个包含 macOS 安装包的版本（包括 Beta），两者独立加载，请求上限为 10 秒。页面切换会取消未完成请求；桌面版本获取失败时提供重试和发布记录入口。

| 结果 | 页面表现 |
| --- | --- |
| 最新 Release 包含可识别的 macOS 安装包 | 列出明确标注 arm64、x64 或 universal 的 DMG/ZIP |
| 404 或最新 Release 没有对应安装包 | 说明暂未找到安装包，提供发布记录和源码入口 |
| 请求失败、超时或返回无效内容 | 显示获取失败并提供重试 |

未标注架构的包不猜测为 Intel，其他系统的 ZIP 不进入 macOS 下载目录。签名、公证与实际可用版本以各次发布说明为准。

## 部署与验收

`pnpm build` 输出到 `dist/`。支持 SPA rewrite 的托管平台可使用 `public/_redirects`；没有 rewrite 时执行 `pnpm build:pages`，为文档、下载及旧入口生成实际 HTML 文件。`vite.config.ts` 是唯一构建配置来源。`main` 的推送通过测试和构建后自动发布至 GitHub Pages。域名为 `biny.online`，域名绑定与 HTTPS 在该仓库的 Pages 设置中管理。

人工检查首页演示、导航、主题、文档搜索、目录锚点与上下篇；在窄屏检查移动菜单和文档目录；在下载页检查失败重试和代码复制反馈。演示需检查会话切换、工具展开、停止、快进停在权限请求、允许/拒绝、重播、输入框菜单和错误反馈；检查放大/收起、键盘焦点、整体缩放，以及向上阅读时的滚动。测试、类型检查与构建通过不表示界面已验收。


下载页按 macOS、Windows、Linux 分组，仅显示发布记录中实际存在的安装包。GitHub API 不可用时使用 `src/lib/release-snapshot.json` 中已核实的发布快照，并在页面注明；它不保证是最新版本。快照于 2026-10-18 从 `binyouo/Biny-Agent` 的 `v0.0.1-beta.2` 发布提取，保留 `tag_name`、`published_at` 和附件的 `name`、`browser_download_url`、`size`。发布新版本后应同步更新该快照。
